# P2 ? Prolog arithmetic equations

These prompts were reconstructed after implementation; they are not a verbatim record of requests sent during development.

## Shared context

Environment: SWI-Prolog 9.x. Inputs are lists of non-negative integers. Expressions use all numbers once in their original order with binary `+`, `-`, `*`, `/`; all intermediate values are integers, and division must be exact with a nonzero divisor. Return equations as strings without spaces. No mutable/global state, parsing strings as terms, initialization directives, or output on load. Use only the assignment's permitted libraries.

For each unit below, use this shared context. Return only the requested definition or test file, followed by a concise explanation of its contract and the results of the specified checks. Distinguish checks actually run from checks proposed, and identify any assumption or unresolved ambiguity. Do not add top-level execution to a solution file or implement the whole problem in one response.

## Contiguous split

> Implement only a predicate that splits a list into two nonempty contiguous sublists in original order. Verify all splits of `[4,2,5]` and failure for `[]` and `[4]`.

## Arithmetic operation

> Implement only the operation predicate mapping an operator and two integers to its result. Division succeeds only for a nonzero divisor and exact integer quotient, including negative intermediate values. Check `6/3`, `5/2`, `1/0`, and `-6/3`.

## Expression generator

> Implement only a recursive expression-tree generator for one nonempty contiguous list, returning a tree and integer value. Use the existing split and arithmetic predicates; enumerate every binary tree and operator choice. Check a singleton and a three-number input; do not build or parse strings.

## Precedence helper

> Implement only a helper assigning precedence to number leaves and the four operators: multiplication/division above addition/subtraction, with leaves highest. Verify both operators in each class.

## Canonical renderer

> Implement only a tree-to-string renderer. Parenthesize a left child if its top precedence is lower than the parent, and a right child if its precedence is equal or lower; never parenthesize a leaf. Verify `8/4*2`, `8/(4*2)`, `1+2+3`, `1+(2+3)`, and `(4+2)*3`.

## Equation generator

> Implement only `generate_equation(List,Equation)`: split into two nonempty sides, generate equal-valued expressions, and return their canonical renderings joined by `=` as an SWI-Prolog string. It must fail for `[]`, `[2]`, and `[2,3,4]`, without an exception or nontermination.

## All equations

> Implement only `all_equations(List,Equations)` using `findall/3` and `sort/2`. Return every distinct generated string in standard sorted order, or `[]`. Verify `[2,4,8]` gives `["2*4=8"]`.

## Equation count

> Implement only `count_equations(List,N)` as the length of `all_equations/2` output. Verify it returns 7 for `[4,2,5,3]` and 0 for `[2,3,4]`.

## Tests

> Create a separate Prolog test file. Compare the full seven-string example for `[4,2,5,3]`; test `[2,3,4]`, `[2,4,8]`, empty/singleton inputs, zero divisors, and both left/right equal-precedence rendering. Assert exact SWI-Prolog strings. The expected seven equations are `4*2-5=3`, `4*2=5+3`, `4-2=5-3`, `4/2=5-3`, `4=2*(5-3)`, `4=2+(5-3)`, and `4=2+5-3`. Include a nested expression whose division is inexact, plus a case with a negative intermediate value.

## Review

> Review P2 for complete ordered binary-tree enumeration, exact division at every node, zero handling, string output, sorting and duplicates, correct parentheses, finite failure on short lists, and prohibited state. Give concrete counterexamples for any failure.
